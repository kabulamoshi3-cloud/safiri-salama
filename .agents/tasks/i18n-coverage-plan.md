## 3. Re-render Subscription Pattern per App

### 3A. Passenger App — Custom `i18n` module with listener pattern

`apps/passenger-app/i18n/index.ts` is a custom singleton with `subscribe(fn)` / `setLanguage(lang)`. It does **not** use react-i18next. Every screen that needs to re-render when the language changes must:

1. Import `i18n` from `'../i18n'`.
2. Call `i18n.t(key)` for every displayed string.
3. Add a `useEffect` that subscribes to language changes and forces a re-render with a local `useState` counter (or force-update pattern). The canonical pattern is:

```tsx
// Inside the component
const [, forceUpdate] = useState(0);
useEffect(() => {
  return i18n.subscribe(() => forceUpdate(n => n + 1));
}, []);
```

This pattern is the **only correct approach** for this custom module because it lacks a React context. Every screen that calls `i18n.t()` must include this hook or its text will freeze after a language change.

### 3B. Driver App — react-i18next with `useTranslation()`

`apps/driver-app/src/i18n/index.tsx` wraps the standard i18next library with `initReactI18next` and exports `I18nProvider`. Screens use `const { t } = useTranslation()`. Because `I18nextProvider` is a React context, **`useTranslation()` automatically re-renders** when `i18n.changeLanguage()` is called — no manual subscription needed.

The SettingsScreen already calls `i18n.changeLanguage(lang)` correctly. The only issue is that screens using `const { t } = useTranslation()` need to actually call `t()` for every string — currently several screens bypass it entirely (EarningsScreen, NavigationScreen, RatePassengerScreen have no `useTranslation()` call at all).

Fix for those screens: add `const { t } = useTranslation();` at the top of the component and replace all hardcoded strings with `t('namespace.key')`.

### 3C. Admin Panel — react-i18next with `useTranslation()`

Same as driver-app. The admin panel's `i18n.ts` initialises i18next with `initReactI18next`. All pages use `const { t } = useTranslation()`. Language toggling (if added) would call `i18n.changeLanguage(lang)` and all components would automatically re-render. Currently the admin panel has no language-toggle UI — it defaults to `'en'`. If a language toggle is needed, add it to the Settings page.

## 4. SettingsScreen Language Toggle — Current State & Issues

### 4A. Passenger App `screens/SettingsScreen.tsx`

**What it does:**
- Renders two `TouchableOpacity` rows for English and Kiswahili with flag emojis and a checkmark on the active language.
- On press: calls `setLanguage(lang)` on the local state AND `await i18n.setLanguage(lang)`.
- Shows an `Alert.alert` with hardcoded bilingual strings confirming the change.

**Two bugs:**
1. **Does not re-render on language change.** The component reads `i18n.getLanguage()` once at mount for the initial `language` state, but it never subscribes to the i18n listener. So the section titles (language, notifications, safety, about) rendered via `i18n.t()` will be stale until the user navigates away and back.
2. **Alert strings are hardcoded** (`'Lugha imebadilishwa'` / `'Language changed'`, `'Kiswahili kimechaguliwa'` / `'English selected'`) rather than using `i18n.t()`.

**Fix:** Add the `forceUpdate` subscribe pattern (see §3A) and replace the hardcoded Alert strings with `i18n.t('language_changed')` / `i18n.t('english_selected')`.

### 4B. Driver App `src/screens/profile/SettingsScreen.tsx`

**What it does:**
- Renders two `TouchableOpacity` rows for English / Kiswahili.
- Calls `i18n.changeLanguage(lang)` on press (correct, triggers re-render via react-i18next).
- Shows a checkmark if `i18n.language === lang`.

**One bug:**
- Uses `t('profile.language')` as the section title, but the `profile` namespace does not exist in `en.json` or `sw.json`. This will silently render the key string `"profile.language"` as literal text.

**Fix:** Add a `profile` namespace to both locale files (see §2B) or change the key to one that does exist (`t('status.available')` is not right — just add `"profile": { "language": "Language" }` to both JSON files).

### 4C. Admin Panel

No language toggle UI. The admin panel always shows English. If a toggle is wanted, add a `<select>` to `Settings.tsx` that calls `i18n.changeLanguage(lang)` — components will auto re-render via react-i18next context. This is optional for a back-office tool.
